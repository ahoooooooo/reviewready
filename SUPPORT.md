# Support

ReviewReady is maintained on a best-effort basis without a response-time or
availability guarantee.

## Where to ask

- Use [GitHub Discussions](https://github.com/ahoooooooo/reviewready/discussions)
  for usage questions, policy design, and integration help.
- Use the structured [issue forms](https://github.com/ahoooooooo/reviewready/issues/new/choose)
  for reproducible bugs and focused feature requests.
- Use the private process in [SECURITY.md](SECURITY.md) for suspected
  vulnerabilities. Never disclose a vulnerability, token, private repository
  content, or third-party personal data in a public issue.
- Use the private maintainer contact described in
  [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for sensitive conduct reports.

Before asking for help, check the current README, supported-version policy, and
existing issues. Include the ReviewReady and Node.js versions, integration mode
(CLI, advisory Action, or protected workflow), a minimal redacted policy, the
observed result, and the result you expected.

## Scope

Maintainers can help explain the released CLI, Action, schemas, documented audit
surface, and reference workflows. They cannot guarantee custom repository
rules, third-party Actions, private infrastructure, or an undeployed hosted
GitHub App. Readiness reports evidence presence only; they are not code-review,
security, legal, or compliance advice.

Support questions do not create a release commitment. Accepted product work is
tracked in a focused issue and follows [CONTRIBUTING.md](CONTRIBUTING.md).
