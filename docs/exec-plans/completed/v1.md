# v1 implementation plan (completed)

Status: the v1 product contract, implementation, npm publication, and Git tags
are complete. Ongoing maintenance and missing historical GitHub Release objects
are tracked separately from this implementation plan.

## Goal

Deliver a publishable Node 22+ CLI and Node 24 JavaScript GitHub Action that
implement the v1 product contract with deterministic behavior and a documented
security boundary.

## Delivery loop

For each vertical slice:

1. record acceptance examples;
2. add a failing focused test;
3. implement the smallest behavior;
4. run focused and full tests;
5. inject malformed and adversarial inputs;
6. fix defects and retain them as regression tests;
7. update public documentation and this decision log.

## Decision log

- 2026-07-22: Use TypeScript on Node 22+ for the CLI and Node 24 for the
  JavaScript Action so the CLI is usable across the active LTS line.
- 2026-07-22: Keep the engine platform-independent and free of I/O.
- 2026-07-22: Keep v1 deterministic and serverless; no model or database
  dependency.
- 2026-07-22: Read effective policy from the base commit and fail closed.
- 2026-07-22: Bootstrap Codex with a short map and workspace permissions; add
  hooks and skills only after a repeated workflow or failure justifies them.
- 2026-07-22: Do not claim AGM compatibility without a published
  interoperability contract and author agreement.
- 2026-07-22: Direct competitor ReviewGate validates the problem but owns
  general PR-shape heuristics; ReviewReady remains focused on repository-owned
  evidence obligations and makes no uniqueness claim.
- 2026-07-22: Support `pull_request_review` events and require workflow ordering
  after checks named by policy.
- 2026-07-22: Publish under the aligned ReviewReady brand,
  `@ahoooooo/reviewready` npm package, and `ahoooooooo/reviewready` repository
  coordinates. npm rejected the unscoped name as too similar to `review-ready`;
  the scope preserves the product and CLI names without evading that safeguard.
- 2026-07-22: Escape untrusted Markdown control characters in one pass and
  HTML-encode ampersands and angle brackets so reports preserve literal text and
  static analysis can verify complete sanitization.
- 2026-07-22: Fully unpublish npm v1.0.0 and v1.0.1 after personal email metadata
  was found in registry history. Preserve the public GitHub project, recover as
  v1.0.2, and make npm's planned tarball pass an allowlist and sensitive-content
  audit before future publication.
- 2026-08-10: Re-ran the complete quality gate after formatting normalization
  and the minimal lockfile security update: 79 tests passed, coverage thresholds
  were met, and npm audit reported zero vulnerabilities.
- 2026-08-10: Published `@ahoooooo/reviewready@1.0.2`; verified registry
  metadata, package integrity, and a clean exact-version install. Public
  `v1.0.2` and `v1` tags pointed to the verified release commit.
- 2026-08-10: Published `@ahoooooo/reviewready@1.0.3` from merged release commit
  `14147f5` after PR #8 and passing Node 22 and Node 24 CI. Verified registry
  metadata, package integrity, exact-version install, policy validation, and a
  ready fixture check. Public `v1.0.3` and `v1` tags point to that commit.
- 2026-08-10: Hardened the v1 evidence boundary with structured requirement keys,
  fenced-Markdown parsing, timestamp-aware latest reviews, commit-status
  evidence, bounded-pagination fail-closed behavior, and runtime/schema parity
  tests. `merge_group` remains unsupported until a trustworthy per-PR
  aggregation contract exists.
- 2026-08-11: Audited release metadata and found that v1.0.2 and v1.0.3 had Git
  tags but no GitHub Release objects. Corrected the historical evidence and added
  a release checklist that treats npm, Git tags, GitHub Releases, the stable
  Action tag, and Marketplace metadata as separate resources.
