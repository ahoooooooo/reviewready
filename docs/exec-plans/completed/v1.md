# v1 implementation plan (completed)

Status: the v1 product contract, implementation, npm publication, and Git tags
are complete. Ongoing maintenance and missing historical GitHub Release objects
are tracked separately from this implementation plan.

## Goal

Deliver a publishable Node 22+ CLI and Node 24 JavaScript GitHub Action that
implement the v1 product contract with deterministic behavior and a documented
security boundary.

## Delivery loop

For each vertical slice:

1. record acceptance examples;
2. add a failing focused test;
3. implement the smallest behavior;
4. run focused and full tests;
5. inject malformed and adversarial inputs;
6. fix defects and retain them as regression tests;
7. update public documentation and this decision log.

## 2026-08-11 integration decisions

- Restore the v1 public requirement-key format while keeping structured
  internal identities. Reject literal backslashes in Git paths, retain both
  sides of renames, ignore hidden Markdown evidence, and describe human
  attestation checks as visible checked text only.
- Stage GitHub evidence collection by the triggered requirement types, bound
  reviewer permission concurrency, reduce latest Check Run and legacy status
  identities with a conservative same-name cross-provider aggregate, and bind
  collection to a verified pull-request snapshot with one bounded retry.
- Preserve same-name Check Runs from multiple App identities as both
  app-specific evidence and a latest unqualified aggregate. Keep pending or
  unknown conclusions as non-satisfying normalized evidence so a provider
  success cannot mask ambiguity.
- Record the trusted workflow-root design in
  docs/adr/0001-trusted-workflow-root.md. The normal pull_request sample remains
  advisory until the repository's GitHub workflow and ruleset settings are
  separately protected and verified.
- Reject an upstream pagination page that exceeds its requested page size or
  the cumulative v1 evidence limit; do not trust a provider that violates the
  bounded collection contract.
- Keep the CLI file-reader hard limit invariant for every caller, including
  explicit helper arguments; reject any requested limit above the bounded
  maximum so the helper cannot bypass the CLI trust boundary.
- Require every Check Run to carry the requested immutable head SHA when the
  gateway is called with a commit ref; branch refs remain endpoint-bound.
- Treat GitHub-nullable queued/in-progress timestamps as absent pending
  metadata, but never allow them to produce a successful conclusion.
- Read required GitHub evidence twice with a bounded canonical fingerprint and
  verify the pull-request snapshot after the second read; retry when either
  evidence or metadata changes.
- Treat malformed or non-contiguous pagination Link next URLs as incomplete
  evidence instead of silently accepting a truncated page sequence.
- Never let a Check Run or commit status with invalid timestamp ordering select
  a successful conclusion from the other provider's same-name evidence.
- Preserve raw Markdown syntax while removing invisible content only for
  visibility checks; quoted HTML attributes and named invisible entities are
  treated as untrusted structure.
- Sanitize control characters in all public ReviewReady errors and reject
  ambiguous duplicate CLI path options before reading files.

## 2026-08-11 follow-up phase

The next delivery is intentionally split from readiness:

1. Freeze and test the normalized, offline repository-audit contract. It must
   be read-only, bounded, deterministic, and fail closed; its report and SARIF
   version must remain separate from the readiness schema.
2. Add pure trusted-ingress primitives for raw-body HMAC validation, atomic
   replay claims, freshness, and SHA/policy/workflow binding. Do not add a
   server, credentials, or deployment until those interfaces are reviewed.
3. Add bounded static AI-workflow source/prompt/sink analysis with fixtures and
   distinct prompt-injection, code-execution, capability, and provenance
   findings. Never execute workflows or invoke an LLM.
4. Dogfood the audit against a checked-in normalized ReviewReady fixture, then
   update architecture, security, CLI, package, and release evidence only after
   focused tests and the complete gate pass.

The pure/live GitHub settings collector, bounded GitHub App authentication
helpers, and webhook ingress/result-binding contracts are now implemented as
read-only library/CLI surfaces. A production HTTP service, durable replay
storage, organization policy, secret rotation, and merge-gate deployment remain
deferred until their permissions, freshness, privacy, and operational contracts
are separately demonstrated.

The audit contract was tightened during adversarial review: active rulesets
must carry a bounded branch/ref scope that covers the evaluated default branch;
all normalized workflows are checked for trusted-root protection to reduce
same-name check spoofing; check/status/deployment write permissions are
reported; and workflow finding caps emit an explicit incomplete result instead
of silently dropping findings.
